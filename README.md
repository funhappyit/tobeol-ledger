# 토벌 장부 (tobeol-ledger)

**[tobeol-ledger.vercel.app](https://tobeol-ledger.vercel.app)**

치이카와(먼작귀) 굿즈 **토벌 기록과 지출·플미 분석** 서비스.

사고 싶은 굿즈를 모아두고, 손에 넣은 굿즈의 실제 지출을 기록하면
**정가 대비 얼마나 비싸게 샀는지(플미)** 를 집계해서 보여줍니다.

굿즈는 세 스토어에서 자동으로 모읍니다. 지금 1만 1천 5백여 건.

## 무엇이 다른가

기존 도감 서비스에는 위시리스트와 수집 체크는 있지만 **지출과 프리미엄 분석이 없습니다.**
이 프로젝트의 중심은 거기입니다.

- 정가로 산 것과 플미를 주고 산 것을 구분
- 플미액·플미율 계산 (구매 시점 정가·환율 스냅샷 기준)
- 플미로 더 쓴 총액, 가장 비싸게 산 굿즈, 캐릭터별·종류별 지출 분포

## 플미 계산 방식

구매 기록에는 **그 시점의 정가(엔)와 환율을 복사해 저장**합니다.
정가가 개정되거나 환율이 움직여도 과거 기록의 플미율이 흔들리지 않아야 하기 때문입니다.

```
정가_원화환산 = 정가(엔) 스냅샷 × 환율 스냅샷 × 수량
상품_순지출   = 실지출(원)                      (배송비·수수료 제외)
총지출        = 실지출 + 배송비 + 수수료
플미액        = 상품_순지출 - 정가_원화환산
플미율(%)     = 플미액 / 정가_원화환산 × 100
```

배송비와 대행수수료는 플미와 **분리**해서 보관합니다.
배대지 수수료를 플미에 합치면 실제 프리미엄이 과장되기 때문에,
통계는 "순 상품가 기준"과 "총지출 기준" 두 가지로 보여줍니다.

환율은 ECB 기준 자동 조회값이라 실제 카드·대행 결제 환율과 차이가 납니다.
자동으로 채우되 **사용자가 수정할 수 있고**, 수정 여부를 따로 기록합니다.

## 어떻게 돌아가는가

```
GitHub Actions (cron)  →  수집  →  Supabase 적재
                                        ↓
                        Vercel (Nuxt)  읽기 + ISR 5분 캐시
```

**수집을 Vercel Cron 으로 돌리지 않습니다.** 공식몰 수집이 2~3분, 포켓 수집이
5~6분 걸리는데 Vercel 함수 한도는 Hobby 60초 / Pro 300초입니다. 그래서 수집은
Actions 가 맡고 Vercel 은 읽기만 합니다.

덕분에 스토어와 DB 에 가는 요청 수가 **방문자 수와 무관**해집니다.
크론이 하루에 도는 횟수로 고정됩니다.

**ISR 로 캐시하는 화면은 누구에게나 같은 화면뿐입니다**(`/`, `/dex`).
캐시된 HTML 은 모든 방문자에게 그대로 나가므로, 개인 자료가 실리는 `/ledger` 는
캐시하지 않고 머리글의 로그인 표시도 브라우저에서만 그립니다.

## 기술 스택

| 영역 | 사용 |
| --- | --- |
| 프레임워크 | Nuxt 4 (Vue 3) |
| 스타일 | Tailwind CSS v4 |
| 백엔드 | Supabase (Postgres + Auth + RLS) |
| 배포 | Vercel (ISR) |
| 자동 수집 | GitHub Actions (cron) |
| 수집 | TypeScript 스크립트 (tsx + curl) |
| 환율 | frankfurter.app (ECB 기준, 과거 일자 조회) |

## 로컬 실행

```bash
npm install
cp .env.example .env.local   # 값 채우기
npm run dev
```

굿즈를 어디서 읽을지 못박고 싶으면 `ITEMS_SOURCE` 를 씁니다.
기본값은 DB 를 먼저 보고, 비어 있거나 응답하지 않으면 수집본 파일로 넘어갑니다.

```
ITEMS_SOURCE=db      # DB 만. 실패해도 수집본 파일로 넘어가지 않음
ITEMS_SOURCE=files   # 수집본 파일만. 수집 결과를 바로 확인할 때
```

## 굿즈 수집

평소에는 Actions 가 알아서 돕니다.

| 대상 | 주기 | 요청 수 |
| --- | --- | --- |
| 공식몰 | 매일 03:00 KST | 86회 |
| 포켓 스토어 | 일요일 04:00 KST | 260회 |
| 모구모구 본포 | 매월 1일 05:00 KST | 3회 |

주기를 나눈 이유는 무게와 신상 주기가 달라서입니다. 공식몰은 상품 JSON 을 250건씩
받아 86회면 끝나고 신상·재입고가 잦습니다. 포켓 스토어는 상품 페이지를 하나씩 읽어
260회가 듭니다. 모구모구 본포는 요청이 3회로 가장 가볍지만, 지역 한정몰이라 신상이
두 달에 한 번쯤 들어와서 자주 받을 이유가 없습니다.

Actions 탭의 **Run workflow** 로 스토어를 골라 수동 실행할 수 있고, 직접 돌릴 수도 있습니다.

```bash
npx tsx scripts/collect-items.ts      # 공식몰
npx tsx scripts/collect-pocket.ts     # 포켓 스토어
npx tsx scripts/collect-mogumogu.ts   # 모구모구 본포
npm run load                          # 수집본을 Supabase 에 적재
```

스토어마다 산출물을 따로 둡니다(`data/items.jsonl`, `data/items-pocket.jsonl`,
`data/items-mogumogu.jsonl`). 한쪽 수집이 실패해도 다른 쪽 수집본이 남습니다.

### 포켓 스토어를 따로 다루는 이유

이 스토어는 태그도 한국어 상품명도 주지 않습니다. 대신 상품명이 규칙적입니다.

```
ちいかわぽけっと  ピクニック な マスコット （ちいかわ）
└─ 시리즈 ────┘  └ 테마 ┘      └ 품목 ┘  └ 캐릭터 ┘
```

그래서 캐릭터·종류·한국어 이름을 모두 **상품명에서** 뽑습니다.
어휘(`src/lib/collect/vocab.ts`, `pocket-name.ts`)를 보강한 뒤에는 다시 받지 않고
해석만 고칠 수 있습니다.

```bash
npx tsx scripts/collect-pocket.ts --reparse   # 요청 없이 분류·번역만 다시
```

### 모구모구 본포를 따로 다루는 이유

후시미이나리·카와고에·오타루 세 점포의 **지역 한정 굿즈**를 파는 스토어입니다.
공식몰과 같은 Shopify 라 상품 JSON 을 그대로 받지만, 붙이는 말이 다릅니다.

발매일 태그가 숫자가 아니라 자연어입니다.

```
공식몰    20261127
모구모구  2026年11月13日発売商品 / 2025年9月12日 発売商品 / 2025年3月20日 新着商品
```

전각 공백·반각 공백·공백 없음이 섞이고 `発売`/`新着` 두 가지가 쓰여서 전용 파서를 둡니다.
한국어 로케일도 없어서(`/ko/` 가 404) 상품명은 사전으로 번역합니다
(`src/lib/collect/mogumogu-name.ts`).

대신 `product_type` 이 알찹니다(59종). 공식몰은 로케일마다 값이 달라 못 믿었지만
이 스토어는 일본어 하나뿐이라 품목어(`箸置き`, `ミニお守り`)가 그대로 들어 있어
종류 판정에 씁니다.

지역(`伏見稲荷`·`川越`·`小樽`)은 분류로 만들지 않았습니다. 태그 원문이 남아
도감 검색으로는 걸립니다.

```bash
npx tsx scripts/collect-mogumogu.ts --reparse   # 요청 없이 분류·번역만 다시
```

## 환경변수

| 이름 | 로컬 | Vercel | GitHub Secrets |
| --- | :-: | :-: | :-: |
| `NUXT_PUBLIC_SUPABASE_URL` | ✓ | ✓ | ✓ (`SUPABASE_URL`) |
| `NUXT_PUBLIC_SUPABASE_KEY` (publishable) | ✓ | ✓ | |
| `SUPABASE_SERVICE_ROLE_KEY` (secret) | ✓ | **✗** | ✓ |

`service_role` 키는 RLS 를 통째로 우회합니다. 앱은 읽기만 하므로 publishable 키로 충분하고,
이 키를 Vercel 에 두면 서버 코드가 실수로 집어 쓸 길이 생깁니다. 적재하는 쪽에만 둡니다.
`.env.local` 은 커밋하지 않습니다.

## 데이터 출처

굿즈 이름·정가·발매일 등 상품 정보는 공식 온라인 스토어가 **공개한 상품 데이터**를 참고합니다.
각 스토어의 `robots.txt` 가 막은 경로는 사용하지 않고, `sitemap` 이 공개한 주소와
검색엔진용 구조화 데이터(schema.org)만 읽습니다.
상품 이미지는 자체 저장하지 않고 원본 CDN을 참조합니다.

## 고지

이 프로젝트는 원작자 및 공식 판매처와 **아무 관련이 없는 비공식 개인 프로젝트**입니다.
모든 캐릭터·이미지·디자인의 저작권은 원작자 ナガノ(Nagano) 및 정식 라이선시에게 있습니다.
권리자의 요청이 있으면 즉시 해당 내용을 삭제합니다.
